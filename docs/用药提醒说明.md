# 本地定时用药提醒

## 使用

1. 首页进入“用药提醒设置”。
2. 允许通知，并允许系统“闹钟和提醒”特殊权限。
3. 返回设置页点击“开启用药提醒”。已有计划也会安排，无需重新录入。
4. 添加或修改计划到当前时间之后 2～3 分钟，按 Home 返回桌面等待通知。
5. 点击通知进入对应详情，确认服药后通知消失。

提醒默认关闭。每日计划按本地日历安排下一次；仅一次计划在下次到达所选时分时提醒，触发后不因重新进入首页而再次安排。修改保存该计划可重新安排。关闭开关会取消系统闹钟并移除通知，但保留药品和单次提醒的完成状态。

当天已记录服药的计划会跳过当日通知。提醒只显示已有计划，不提供用量建议；“今日已服药”仍是用户主动确认的结果。

## 代码结构

- `ReminderTime`：计算下一次本地计划时间，比较日期；纯 Java，可运行单元测试。
- `ReminderManager`：通知渠道、开关、持久化安排、安排与取消闹钟、读取记录并发送通知。
- `MedicineReminderReceiver`：接收显式闹钟、开机、应用更新、时间与时区变化和精确闹钟授权变化；使用 `goAsync` 短暂异步查询。
- `ReminderSettingsActivity`：权限引导和总开关。

原代码仅接入：首页增加设置入口和恢复调用；数据库帮助类在新增、修改、删除、标记服药成功后通知提醒模块。不修改数据库版本、字段、表单或详情页操作流程。

安排状态放在独立 SharedPreferences 中，每条计划保存下一次触发时间。`0` 表示单次提醒已处理；不存在表示需要首次安排。系统闹钟用含主键的 URI 区分，防止不同药品互相覆盖；触发时核对保存的时间以忽略旧安排。

## 恢复与限制

- 设备重启解锁后、应用更新、重新打开首页、重新授权精确闹钟时，恢复保存的安排。
- 时间或时区改变后，未完成的计划重新按本地时分安排。
- 同日错过的提醒在恢复时尽快处理，可能晚于原计划；跨日期的过期通知不补发，避免误导服药。每日计划继续安排下一次。
- 正常返回桌面仍可提醒；强行停止、关机、权限撤销、勿扰及设备省电策略可能影响提醒或声音。不承诺医疗级可靠性。
- 权限被拒绝后请到系统应用设置中检查；开启总开关不等于所有通知展示设置都保持允许，设置页会显示权限状态。
- 没有加入无限重复催促、短信发送或“稍后提醒”动作。

## 验收清单

- [ ] 首次安装，拒绝权限时不崩溃；权限未齐全不能开启。
- [ ] 允许两项权限，新增 2～3 分钟后的计划，后台收到通知。
- [ ] 两条不同计划分别提醒，点击进入各自详情。
- [ ] 单次触发后重开首页，不重复安排；每日计划安排下一次。
- [ ] 修改计划时间后旧时间不提醒；删除计划后不再提醒。
- [ ] 当天已确认服药的计划到点不通知。
- [ ] 关闭开关后不提醒；重新开启恢复未完成计划。
- [ ] 重启后恢复；改变时间/时区按本地时间重排。
